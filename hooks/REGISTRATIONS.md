# Hook registrations — rationale

Why each registration in `hooks.json` exists and is shaped the way it is. `hooks.json` itself
carries only keys the Claude Code hook schema knows — the harness warns on every other key at
boot, and a note inline there reads as an unknown key. A registration's rationale lives here,
under a heading naming its event, matcher and delivered script; the hook-delivery manifest lives
in `effective-delivery.json`, written by `scripts/emit_effective_delivery.py`.

Sections follow `hooks.json` registration order.

## SessionStart · `startup|resume|clear|compact|fork` · `sessionstart-dispatch.py`

SESSIONSTART-HEAD-LEGS (tripwire-registry/sessionstart-head-legs.md). The sync fan-in's REGISTRY opens with three head legs, in this order, ahead of every other leg:

- Leg 0, `session-start-repin-cloud-engine-root.py`, all five sources. Thin shim for the engine op `hooks.repin_cloud_engine_root`: when `CLAUDE_CODE_REMOTE=true` it atomically re-points the cloud engine-root symlink `scripts/cloud_setup.py` pins (frozen at install onto `/root/klabauter`) onto a fresher, stamped, per-session-mounted `claude-klabauter` checkout, when one exists. Every engine-root reader in this chain, this repo's own `_engine_root` ladder included, follows that symlink, so this leg completes before any later leg resolves the engine root. It emits zero stdout on every path, which keeps the next head leg at stream offset 0. Inert off-cloud; no spawn; fails open at every step. After it returns the dispatcher removes every `coordinator_core` module from `sys.modules` and restores `sys.path`, so the following legs import the engine fresh through the repointed symlink instead of mixing pre-repin and post-repin modules. Importing the op through whatever engine root currently resolves is not a chicken-and-egg problem: the op's body performs no version-sensitive work, only filesystem operations against its own injectable path constants. Order pinned by `test_sessionstart_repin_cloud_engine_root_first.py`.
- Head leg 1, `session-start-watch-presence.py`, all five sources. Group EM watch presence: a presence FACT (a Group EM holds this repo's standing and can be reached by name, when the heartbeat names a holder) plus `GROUP EM WATCH: <verdict>` read from state/group-em-watch.json via coordinator/skills/group-em/watch_heartbeat.read_watch, joined against the live session registry, plus the Uhura holder -- reported, never acted on. Resident-fact assertion that re-fires at every fresh-context boundary, so it takes the full matcher. Every failure mode degrades to silence.
- Head leg 2, `session-start-cloud-focus.py`, `startup` only. Inert outside a cloud session (`coordinator_core.env_locality` harness rung). For `COORDINATOR_CLOUD_FOCUS_REPO` locates the checkout and points the session at `coordinator:cloud-channel`, which writes the anchor commit and opens and subscribes the draft PR only the model can create. The line is an instruction the session must act on. `startup` only: the other sources fire mid-execution. Spawns nothing; fails open; exits 0 on every path.

Head legs ride this fan-in because the harness inlines only the first ~2,048 characters of a hook's stdout: a payload that starts past that window never reaches context. A head leg starts at stream offset 0, and only the head legs ahead of it can push it out, so per-leg ceilings and a head total within the preview window are test-enforced and growth fails a test instead of truncating. A leg whose own `additionalContext` envelope reaches the dispatcher is unwrapped to its text before it is written. Each leg's output is flushed as soon as that leg returns.

## UserPromptExpansion · `*` · `userpromptexpansion-dispatch.py`

USERPROMPTEXPANSION FAN-IN -- the single UserPromptExpansion entrypoint, `async: false`, timeout 45s, internal deadline 40s. UserPromptExpansion fires ahead of UserPromptSubmit on a typed slash-command invocation and carries pre-parsed command_name/command_args. The dispatcher normalises command_name to a bare verb (any `<namespace>:` prefix and leading `/` stripped), lazy-imports only the legs whose verbs match, runs them concurrently on daemon threads under the shared deadline (never a ThreadPoolExecutor, whose atexit join would defeat it), and composes ONE envelope with contexts joined in REGISTRY order. A crashing leg or one past the deadline is skipped with a stderr breadcrumb, fail-open for that leg only; the breadcrumb and envelope go through `sys.__stderr__`/`sys.__stdout__`. Exit 0 always. async:false because additionalContext must land in the SAME turn the prompt is being expanded into. Install-surface note: this hook type required /reload-plugins to start firing during the spike that proved the mechanism (state/handoffs/2026-07-23_145600_spike-userpromptexpansion-slash-command-args.md) -- a plain hooks.json edit was not observed to be enough on its own. Each leg keeps its own `compute_context(stdin_text)` and its own fail-open contract:

- `pickup-autofire.py` -- matches the pickup and baton-grab verbs (cheap gate, not a security boundary), computes the pickup-assemble brief through the COORDINATOR_SETTINGS_HOME ladder, and auto-fires the mutating apply half ONLY on coast==clear AND judgment_points==[]. Never blocks /pickup.
- `mise-autofire.py` -- mints a fresh Phase-0 run id through `backlog-grind-assemble mint-run-id mise-en-place`, briefs that id back through `backlog-grind-assemble brief mise-en-place --run-id <minted>`, and injects the id, its implied (not-yet-existing) inventory path and the brief's decision object. Both calls are read-only and the leg must never grow a mutating half; it never creates state/mise-inventory/, whose absence is the engine's own Phase-0-vs-Phase-6 self-gate. A failed mint means the EM mints by hand. Consumer contract: cross-repo/inbox/2026-08-04-engine-repo-em-mint-run-id-verb-shipped.md.
- `handoff-segment-inject.py` -- computes the active case set for coordinator/skills/handoff/residue/'s segment contract (`shared` always, `dirty-tree` from a read-only `git status --porcelain`, `predecessor`/`carried-items` from the read-only `baton-assemble brief handoff` CLI), injects every active segment sorted by `order`. Read-only end to end. Budget-capped by `_CONTEXT_BUDGET_CHARS` (not the 10,000 chars pickup and mise carry), degrading class:droppable segments before any class:protected one. Never blocks /handoff, which fires under context pressure by definition.
- `group-em-autofire.py` -- runs coordinator/bin/group-em-enter.py --json by path and injects the standing verdict, roster, digest and baseline. The CLI MUTATES: it claims the Group EM nomination, and the skill's PM gate is the human typing the verb, so this leg is bound to the typed verb and nothing else. That is why it lives here, on an event only a typed slash command reaches, and never in preuse-skill-dispatch.py, which a model-invoked Skill call can reach. Never wire it to Stop, a timer, or another command. It never passes --supersede and never passes --local. The CLI runs in-process through the forwarder's `_engine_forward.forward()` (runpy by path, same argv), not as a child interpreter. Exit 5/6/7 refusals are reported as context rather than swallowed, because a session told nothing believes it holds a Group EM it does not.

Verb disjointness: `_GROUP_EM_COMMAND_NAMES` shares no verb with any other leg, so the mutating group-em leg always runs alone, which is what makes its in-process forwarder call (it rewrites `sys.path`/`sys.argv` and redirects stdout process-wide) safe.

6. `allow-emitted-workflow-fire.py` (allow on a verifying receipt; `additionalContext` warning on a hand-rolled fire) -- never moved ahead of a deny leg: an allow must not run before a deny that wins.

WORKFLOW-FAN-IN-PRECEDENCE: every leg sees the ORIGINAL payload (no rewrite threading; the sole rewriter makes none needed). First deny in REGISTRY order wins: its envelope is emitted verbatim, later legs are not imported or run, and context from earlier non-deny legs is dropped. With no deny, ONE envelope is composed: `permissionDecision` is `allow` when any leg that ran allowed (else absent), `permissionDecisionReason` joins the allowing legs' reasons in order, `updatedInput` is the sole rewriter's, and every `additionalContext`/`systemMessage` joins in order with a blank line; nothing to say means no stdout. A leg's stderr is replayed in order for the legs that ran. A crashing leg, or one whose non-empty stdout is not JSON, is skipped with a stderr breadcrumb and fails open for that leg only; exit is always 0. Intended delta from six separate hooks: on a denied call a later leg's side effects do not happen (the trampoline's sentinel is not consumed). The same rule governs the Agent and Skill fan-ins; see hook-best-practices.md § Multi-hook deny aggregation.

Timeout: the entry's `timeout` is 15s. The six legs ran in parallel at 5s each; in sequence the worst case is three legs that can reach a spawn or file read, plus headroom. Folding six registrations into one takes PreToolUse from 12 to 7 against the shrink-only `EVENT_REGISTRATION_BUDGET`, with no budget raised.

Narrowed in-script: silent unless the hook process's own `PATH` has a non-path element (placeholder, `$` reference, relative entry). Advisory only; tripwire `A-NON-PATH-PATH-IS-A-BREAK-CLASS-FAULT-REPORTED-NOT-WORKED-AROUND`. Blind by construction when `python3` itself is missing — the first-session `command -v` check covers that arm.

The hook also appends one row per failed WebSearch call (outcome `failure`) to the settings-home WebSearch ledger; contract: `coordinator/contract/websearch-ledger.md`.
