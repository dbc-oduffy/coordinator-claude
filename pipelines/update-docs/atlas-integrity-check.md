# Architecture Atlas Integrity Check

## Overview

The routine runs the mechanical layer first, with no model call, then narrative on changed pages
only. Path resolution, rename lookup and index regeneration are lookups; an agent is dispatched
only for prose, and only on a page the mechanical layer says changed. The contract is
`coordinator/docs/contracts/atlas-mechanical-layer.md`.

**Skip silently if `docs/architecture/systems-index.md` does not exist** — the atlas hasn't been
bootstrapped yet. No error, no warning.

---

## Step 0 — Mechanical layer

Run every leg below, in this order, before any narrative step. No leg dispatches an agent. Each
leg ends `ran`, `no-producer` or `declined`; a `declined` leg carries a reason. `no-producer`
means no deterministic producer exists for this repo today: report it, never hand it to an agent.

1. **`dead-paths`.** Producer: the `atlas-citation-check` launcher, resolved per
   `coordinator/snippets/resolve-coordinator-bin.md`. Findings of class `unresolved-file` and
   `misrooted-file` are dead paths. Exit 1 with findings is the expected result, not a failure of
   the step. Save the output verbatim under `scratch/atlas-mechanical/`; never read it whole (about
   220 KB on a large atlas). Take the count from a count-mode search over the saved file. At or
   under the interim cap of 50, copy the rows into `dead_paths`; above it, `dead_paths` is null
   and the leg's detail carries the count and the saved file's path.
2. **`rename-targets`.** Producer: one `git log -M --diff-filter=R --name-status` query bounded
   by the systems index's `last_mapped` date, saved once under `scratch/atlas-mechanical/`, never
   one query per path. A dead path takes the new path of the rename row whose old path equals it,
   after any trailing line or line-range suffix is cut from the cited span. A target that was
   itself renamed is followed until the path exists on disk; a chain ending on a missing path
   yields null. Above 50 dead paths the leg is `declined` with reason `over-interim-cap` and the
   count; nothing loops.
3. **`file-index`.** Producer: the command `docs/architecture/file-index.md` names after
   `Generated by` in its header. No such line means `no-producer`. `changed` is the generator's
   own summary word (`written` or `unchanged`). `added`, `removed` and `systems_touched` come
   from one zero-context `git diff` of the file; above 50 changed rows they are null and the
   detail carries the row count. A rewritten `file-index.md` folds into the Phase 9 commit.
4. **`connectivity-matrix`.** `no-producer`. The matrix is not regenerated by an agent: an agent
   rebuilding it is a model paid to guess at edges a graph holds exactly, and the result would
   not match the next deterministic run.
5. **`pages-changed`.** The union of: every atlas page carrying a dead path while the dead-path
   count is at or under the interim cap (above it, dead paths add no page and the report carries
   the backlog count), and `systems/<system>.md` for each system in `file_index.systems_touched`
   and `connectivity_matrix.systems_touched`. Pages under `docs/architecture/audit-records/` are
   dated records: counted in `dead_paths`, never in `pages_changed`.

**The report.** Write `scratch/atlas-mechanical/<date>-report.json`, shaped per the contract:
`schema: atlas-mechanical-layer`, `schema_version: 1`, `legs` (keyed by leg id, each
`{status, producer, detail}`), `dead_paths`, `file_index`, `connectivity_matrix`, `pages_changed`.
The Phase 14 Architecture Atlas line quotes the five leg statuses and the `pages_changed` count.

The step edits no atlas page and never rewrites a dead path in place.

## Step 1 — Narrative on changed pages

Narrative reading and any narrative agent run only on `pages_changed`. An empty set means zero
agents and one report line. A non-empty set goes to one narrative agent that takes the pages in
turn; splitting it is the EM's call and is named in the Phase 14 line.

1. **Read `docs/architecture/systems-index.md`** for the named systems and descriptions.
2. **For each listed page**, read its "System Narrative" or "Purpose" section from
   `docs/architecture/systems/{system-name}.md` and the changed files of that system (the
   `file_index` `added` and `removed` rows, plus the merge-base diff names).
3. **Narrative-drift check:** does the narrative mention the subsystem or layer the changes touch,
   and does it still describe the system's role if the change adds a responsibility?
4. **Emit a drift note per mismatch:**
   ```
   NOTE: Narrative drift — [system-name]:
     - [file path]: this file touches [what changed]. The atlas narrative for [system-name]
       does not mention [X]. Consider updating the narrative.
   ```
5. A listed page with neither a drift note nor a `dead_paths` row is not sent to the narrative
   agent. With none flagged, note: `"Atlas narrative check: no drift on [N] changed pages."`

Each narrative brief carries that page's drift notes, its `dead_paths` rows with their targets,
and its system's `file_index` `added` and `removed` rows, so the agent re-derives none of them.

RAG presence (`mcp__*project-rag*` tool available) changes two things only: which producer the
`connectivity-matrix` leg gets once one exists, and the brief's clause telling the agent to query
the index before any grep or file walk.

## Common Mistakes

- **Treating `no-producer` as a cue to dispatch.** A leg with no producer is reported as such; an
  agent asked to "just rebuild the matrix" is the defect this routine removes.
- **Dispatching before Step 0 has run.** Narrative agents are briefed from the report, never
  before it.
- **Reading the saved citation-check output whole.** Count it, and read rows only at or under the
  cap.
- **Treating narrative-drift as a hard blocker.** Drift notes are prompts to update the atlas, not
  reasons to halt work.
- **Editing audit-records pages.** They are dated records: counted, never changed.
