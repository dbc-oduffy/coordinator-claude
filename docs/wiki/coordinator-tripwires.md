- **Destructive-git orphan block (BLOCK-DESTRUCTIVE-GIT-ORPHAN):** PreToolUse(Bash) hook `block-destructive-git-orphan.sh` that re-derives true git state at the tool boundary and DENIES three commit-orphaning ops: (1) `git reset --hard <target>` when `<target>..HEAD` would drop ≥1 commit; (2) plain `git push --force`/`-f` (steers to `--force-with-lease`, which is allowed); (3) `git branch -D <name>` when `<name>`'s commits live on no other local/remote ref. Allows the benign cases (`reset --hard HEAD`/no-target, fast-forward resets, `-d`, merged-branch `-D`, bogus refs). Honors `git -C <dir>`; the `cd <dir> && git …` form is evaluated against cwd (documented v1 limitation). Override: `COORDINATOR_ALLOW_ORPHAN=1` (use ONLY after independently confirming the commits are safe — that confirmation is the point). Script: `hooks/scripts/block-destructive-git-orphan.sh`. Test: `hooks/tests/test-block-destructive-git-orphan.sh` (21 cases, real temp-repo). Origin: 2026-05-28 near-miss — an EM acting on corrupted/flaky tool output (phantom "already merged via PR#47" premise built on SHAs that never existed) proposed `git reset --hard origin/main` on a branch 257 commits AHEAD of main, which would have orphaned a day-plus of work. This hook externalizes the "verify the premise before the irreversible action" rule so it no longer depends on EM discipline or the flaky harness returning honest output. Greppable token: `BLOCK-DESTRUCTIVE-GIT-ORPHAN`.

- **Destructive-rm block (BLOCK-DESTRUCTIVE-RM):** PreToolUse(Bash) hook `block-destructive-rm.sh` — the uncommitted-work sibling of the orphan guard. Re-derives true `git status` at the tool boundary and DENIES an `rm` that would destroy work git CANNOT recover: (1) a recursive `rm` (`-r`/`-R`/`--recursive`) or a directory target that, per fresh `git status --porcelain`, holds untracked files or unstaged edits; (2) deletion of a `.git` store. Disposability is defined BY GIT — fully-committed trees pass, gitignored trees (`node_modules`/`build`/`.venv`) never appear in porcelain so they pass automatically, and targets outside any git repo pass (scratch). On top of git-disposability there is one narrow, condition-matched allowlist for **regenerable coordinator scratch**: a target is exempt from the git-status check ONLY when ALL hold — it lives at exactly `<this-repo-root>/tasks/<name>-scratch` (parent compared by inode via `-ef`, scoped to THIS repo so a sibling repo's same-named scratch does not inherit the exemption), is not a symlink, and its basename matches `^[a-zA-Z0-9_-]+-scratch$`. This closes the `/workday-complete` Step 4f case (regenerable `tasks/daily-review-scratch` tripped the guard every run) without weakening the floor: the allowlist matches *conditions*, never a broad container; preferred v2 is to relocate scratch to a gitignored path so no allowlist is needed. Allows single-file `rm` (low blast radius), `git rm` (staged, recoverable), nonexistent targets. v1 limitations: literal paths only (`$VAR`/glob skipped; `$(...)`/backtick under recursive intent fails SAFE→deny); Bash only — PowerShell `Remove-Item` is an uncovered residual (flagged to PM). Override: `COORDINATOR_ALLOW_RM=1` is read from the **hook-process environment**, NOT an inline `COORDINATOR_ALLOW_RM=1 rm …` prefix (that sets the spawned shell's env, which the hook never sees) — correct-by-design, since an inline-reachable override would let a confabulating model trivially bypass the guard on the very `rm` destroying work; the scratch allowlist removes the routine need for the override. Script: `hooks/scripts/block-destructive-rm.sh`. Test: `hooks/tests/test-block-destructive-rm.sh` (35 cases, real temp-repo). Origin: 2026-05-28 tool-output flakiness near-miss — closes the uncommitted half of the file-loss surface the orphan guard left open (diagnosis: `docs/architecture/audit-records/2026-05-29-tool-output-flakiness-diagnosis.md`). Greppable token: `BLOCK-DESTRUCTIVE-RM`.

- **Git-C-over-cd offer (OFFER-GIT-C-OVER-CD):** PreToolUse(Bash) hook `offer-git-c-over-cd.sh` — a low-stakes REDIRECT, not a destructive guard. Fires ONLY when the first command segment is `cd <path>` AND the second is a `git` invocation, and DENIES with a message that leads with the exact `git -C <path> …` rewrite. Rationale: a leading `cd` makes a compound command that trips a permission prompt rendering as a non-returning `Waiting…` — the stall misread as a flaky channel that drove the 2026-05-30 probe-spray loop (`echo ALIVE`/`printf CHAN_OK`/variant `git log`, broken only by PM interrupt). `git -C` is the exact, prompt-free equivalent, so the redirect is always actionable and false-positive cost is ~zero — that is what keeps a DENY mechanism offer-shaped (block WITH alternative = redirect, per design-as-offers). Deliberately narrow: `cd X && npm i && git status` (second segment not git), a mid-chain `cd` (`ls && cd X && git …`), and `cd X && <non-git>` are all left alone. Does NOT cover the OTHER wiki-named trigger — batched redundant variant-probes across sibling tool calls — because a per-call PreToolUse hook cannot see the batch; that stays doctrine-only. Override: `COORDINATOR_ALLOW_CD_PREFIX=1` from the **hook-process environment** (an inline prefix sets the cd child's env, which the hook never sees). Script: `hooks/scripts/offer-git-c-over-cd.sh`. Test: `hooks/tests/test-offer-git-c-over-cd.sh` (28 cases). Splits only on `&&`/`;`/newline (not `|`/`||`/`&`), bails on cd flag/special-forms (`-`, `-L`, `-P`, `--`), and bails on an unbalanced quote in a segment (a `&&`/`;` inside a quoted git arg) so the suggestion is never malformed. Doctrine: `docs/wiki/tool-output-flakiness-protocol.md` § Not this protocol — blocked / no-return. Greppable token: `OFFER-GIT-C-OVER-CD`.

- **Probe-spray nudge (NUDGE-PROBE-SPRAY):** PreToolUse(Bash) hook `nudge-probe-spray.sh` — offer-shaped, **warn never block** (allow + additionalContext). Catches trigger 2 of the blocked/no-return failure: after an empty/`(No output)`/non-returning result the model sprays liveness probes (`echo probe`/`echo ping`/`printf CHAN_OK`/`sleep 1; echo done`/repeated `git log -1`) that diagnose nothing. Defeats the "a per-call hook can't see the batch" objection with DISK STATE — a session-keyed rolling window (`$TMPDIR/coordinator-probe-spray-<session>.*`) counts probe-shaped commands; at ≥3 within 90s it nudges once (30s cooldown so the nudge isn't itself spam), and any clearly-real command resets the streak. Probe shapes: `echo <single-token>` (bare OR quoted — the real shape is `echo "se-flush-3"`), bare `echo`/`true`/`false`/`:`/`pwd`/`date` no-ops, short `printf` literal, `sleep N`, or a command whose hash recurs ≥2× within a small ring (catches alternating/repeated re-reads while giving legitimately-repeated real commands like `make` latitude). Keyed by `session_id` from the hook's stdin payload (stable across a session) → `CLAUDE_SESSION_ID` → `$PPID`. A single legitimate echo/sleep never nudges. Off switch: `COORDINATOR_PROBE_NUDGE_OFF=1` (echo/sleep-heavy autonomous runs). Script: `hooks/scripts/nudge-probe-spray.sh`. Test: `hooks/tests/test-nudge-probe-spray.sh` (45 cases, stateful sequences). Doctrine: `docs/wiki/tool-output-flakiness-protocol.md` § Not this protocol — blocked / no-return (trigger 2). Origin: 2026-05-30 — probe-spray recurred across concurrent sessions after the doctrine fold alone proved unable to bind a session mid-spray. Greppable token: `NUDGE-PROBE-SPRAY`.

- **Settings-integrity guard (SETTINGS-INTEGRITY-GUARD):** SessionStart hook `guard-settings-integrity.sh` (matcher `startup|clear|compact`) that auto-recovers a clobbered `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/settings.json`. Health predicate: parses as JSON AND `.enabledPlugins` has ≥1 entry (one `jq -e` covers corrupt/stub/no-plugins). On HEALTHY boot it refreshes a cwd-independent snapshot `.settings-last-good.json` (write-on-change only, no mtime churn). On UNHEALTHY boot it restores — snapshot first, git `HEAD:./settings.json` as fallback — saves the clobbered copy to `.settings-clobbered.bak` (forensic), and emits a loud banner telling the operator to `/reload-plugins` (this session already loaded the broken file at boot). **No-snapshot-no-opinion:** absent a healthy snapshot/HEAD it only WARNS, so a genuinely-minimal install (0 plugins) never gets a false restore — that property is what makes auto-restore safe to default on. Lives in the PLUGIN hooks.json, never user settings.json (a guard inside settings.json would be wiped by the very clobber it catches). Targets the fixed config path regardless of cwd → protects every session, not just `cwd=~/.claude`. Both runtime artifacts are gitignored. Complementary hardening: `.gitattributes` pins `/settings.json` + `/settings.local.json` to `eol=lf` (the guard itself is mechanism-agnostic). Script: `hooks/scripts/guard-settings-integrity.sh`. Doc: `docs/wiki/settings-integrity-guard.md`. Greppable token: `SETTINGS-INTEGRITY-GUARD`. Origin: 2026-05-29 — `settings.json` hand-recovered 3+ times (git log `1ad65df0`, `13ffa3db`) after stub-truncation silently disabled all plugins; sibling to `check-dropped-tracked-files.sh`, which only catches worktree *deletions* and misses the truncation shape.

- **Consumed-handoff frozen (CONSUMED-HANDOFF-FROZEN):** [universal] PreToolUse(Write|Edit|MultiEdit|NotebookEdit) hook `block-consumed-handoff-edit.sh` denies edits to any `state/handoffs/*.md` whose YAML frontmatter declares `status: consumed`. Doctrine: a consumed handoff is paper trail; once `/pickup` flipped `status: active → consumed`, the body is FROZEN. The picking-up session's next checkpoint belongs in a SUCCESSOR handoff authored via `/handoff` (writes the new file with `status: active`, `deployment_state: ready_to_fire`, `predecessor: <this-file>`, then chain-archives the consumed predecessor to `archive/handoffs/`). An in-place append of `### <date> session — pickup, …` progress blocks corrupts the audit trail (multiple sessions' progress stapled into one file), bypasses the carry-forward cascade machinery, and is invisible to the pickup index — `/workday-start`, `/pickup`, and the session-init orphan sweep all treat consumed handoffs as historical, so any progress recorded in the body never surfaces as live work for the next opener. The legitimate `/pickup` mutation step is unaffected: at the moment `/pickup` writes the status-flip, the on-disk frontmatter is still `status: active`, so this hook does not see it. Override: `COORDINATOR_OVERRIDE_CONSUMED_HANDOFF_EDIT=1` reserved for recovery-flavor crash-invalidation notes (the handoff skill's recovery sweep writes one-line notes into sibling handoffs that may be `consumed`) and genuine one-off paper-trail corrections — never progress appends. Script: `hooks/scripts/block-consumed-handoff-edit.sh`. Contact-points: `skills/pickup/SKILL.md § Step 5 frontmatter-mutation negative-spec`, `skills/handoff/SKILL.md § Inverted antipattern`. Greppable token: `CONSUMED-HANDOFF-FROZEN`. Origin: 2026-06-09 — recurring EM behavior across sessions of appending `### session — pickup, +N progress` blocks to the picked-up predecessor instead of running `/handoff`; transcript evidence in the founding commit's message body.

- **Unauthorized-handoff nudge (NUDGE-UNAUTHORIZED-HANDOFF):** PostToolUse(Write) hook `nudge-unauthorized-handoff.sh` that surfaces an offer-shaped nudge — **warn, never block** — when a new file is Written into `state/handoffs/` or `tasks/spinoffs/` without an authoring skill (`/handoff`, `/workstream-complete`, `/spinoff`) detected. The nudge leads with the better alternative (commit-and-stop / `/workday-complete` for tidy-stop reflex; `cross-repo-memo` CLI for cross-repo messaging; the gated skills for genuine forks) and explicitly says "if deliberate, proceed." **Mechanism:** PostToolUse + `exit 2` — the file is already on disk (cannot be blocked) and stderr is fed into the model's next turn; this is the only warn-reaches-the-model-without-blocking channel (PreToolUse `exit 2` *blocks*; `exit 0`+stderr fails silent — see `hook-best-practices.md` § Friction-as-warning). **Why a nudge, not a block:** the predecessor `block-unauthorized-handoff.sh` was a PreToolUse Form-A deny that twice false-blocked a PM-authorized `/spinoff` (2026-05-28) — its transcript-scrape (looking for `<command-name>` tags / `/spinoff` strings) is unreliable (Skill tool emits no `<command-name>`; large tool outputs bury the invocation past the grep window). A *block* gated on an unreliable signal fails CLOSED (denies authorized work). The rework keeps the same best-effort scrape but uses it to SUPPRESS a non-blocking nudge — failing OPEN: at worst one extra nudge the EM reads and proceeds past. The signal didn't get more reliable; the consequence of its unreliability got cheap (design-as-offers). Silence in autonomous runs: `COORDINATOR_HANDOFF_NUDGE_OFF=1` (quiets the nudge; it is NOT an authorization gate — there is nothing to authorize, since nothing is blocked). The doctrine it backs (handoffs/spinoffs are PM-gated, not tidy-stop ceremonies) is also enforced by the skill Step-0 gates (`skills/spinoff` Step 0, `skills/handoff` Step 0); this hook is defense-in-depth at the tool boundary. Script: `hooks/scripts/nudge-unauthorized-handoff.sh`. Test: `hooks/scripts/tests/test-nudge-unauthorized-handoff.sh` (8 cases; asserts the never-block invariant on every case + reproduces the 2026-05-28 shape). Greppable token: `NUDGE-UNAUTHORIZED-HANDOFF`.

## Override Flags as Latent-Rot Signal

Safety-gate failures that surface when an override flag is used can be latent-broken since the gate was authored. When a check or probe is guarded by an override flag, the flag's existence is a smoke signal — not evidence that the gate works when the flag is absent. Before reaching for an override, read the probe's actual code and verify that the no-override path behaves as documented on the current substrate.

Specifically: a probe that was written against an older install shape, a probe whose sentinel file never gets created on clean installs, or a probe with a syntax error in its main body will all "work" (silently pass or error-suppress) under the override while being completely broken in the default path. The pattern is: gate was added → subsequent install-surface change made the gate's logic wrong → override was added "temporarily" → override became permanent → gate is now theater.

**Rule:** any use of an override env var for a safety gate requires reading the gate's source before invoking the override — not after, not as a follow-up. If the gate is genuinely broken, fix it or remove it; if it's correct, the override is not needed. Override-and-continue is only legitimate when the override's semantics match the actual situation (e.g., `COORDINATOR_OVERRIDE_ACCEPTANCE_GATE=1` when the host topology genuinely cannot reproduce the AC environment). (Source: 2026-05-24 project-rag-ue-addon)

## Existence-checks are not behavior-gates — pair with `bash -n`

A tripwire battery that asks "does the file exist?" and "does the registry list it?" does NOT answer "does this script parse?" or "does it run?". A probe/helper shell script that crashes at line 1 satisfies every existence / inventory / verdict-lint tripwire while delivering zero diagnostic value — every wrong path is non-empty, it just points at nothing. Two 2026-05-21 instances: doctor probes shipped with invalid here-doc syntax (unterminated `<<'PYEOF'`) and an `Accept: application/json` header against an SSE endpoint, all green on the existence battery.

**The cheap floor is `bash -n`** (syntax-only, zero runtime cost) across `commands/lib/**.sh` and `**/probe-*.sh` — it would have caught the parse error. Runtime coverage (probe-against-live-daemon smoke at session-end / workday-start) catches the protocol-shape class but is heavier. Add the `bash -n` floor to CI for any agent-facing diagnostic tool whose substrate is shell scripts; the existence-check anti-pattern generalizes anywhere a tripwire asserts *presence* rather than *behavior*. Pairs with the wiring-layer-conformance lesson — file-level conformance ≠ runtime registration. (And note the CRLF caveat: on a Windows working tree with `core.autocrlf=true`, `bash -n` itself false-positives on heredoc-heavy scripts — see `claude-code-platform-gotchas.md` § Windows bash / CRLF; ShellCheck is the real lint.)

- **Game-dev source guard (`COORDINATOR-GAMEDEV-GUARD`):** Pre-rsync hook at `setup/percolate-hooks/coordinator-claude/pre-rsync/10-guard-no-game-dev.sh`. Fires before any file is transferred to the OSS coordinator-claude publish destination. Aborts the publish (exit 1, no destination mutation) if `plugins/game-dev/` exists in the mirror source set. Offer-shaped message leads with the remedy: game-dev is holodeck-owned and ships via the holodeck distribution, not the OSS coordinator-claude release. Override: `COORDINATOR_OVERRIDE_GAMEDEV_GUARD=1` — exceptional use only (fixture authoring, mechanics testing); see § Override Flags as Latent-Rot Signal before using. A second override, `COORDINATOR_PLUGIN_ROOT`, redirects the source root for test fixture use (do not set in production). Design note: the guard checks only for the `game-dev/` directory — NOT a tree-wide content-pattern check. The coordinator-claude tree legitimately contains ~68 files referencing `holodeck-docs`/`holodeck-control`/`claude-unreal-holodeck` (cross-repo-communication wiki, peer-repo-polarity, machine-local templates, etc.) and these ship to OSS by design. A content-pattern abort at tree scope would fail-closed on correct content. Spec: `archive/specs/2026-05-26-retire-game-dev-from-oss.md` § C4.

## Complete-the-set actions don't need PM-which-one calibration

When an action set is **bounded and cost-symmetric** (each item costs roughly the same, there's a finite known list, and doing all of them is not riskier than doing one), bias to **do-all** rather than do-1/N-and-ask-about-the-rest. Asking "should I also do the other N−1?" is false-choice ceremony when the subset is bounded and the per-item cost is symmetric — the EM owns that call. This extends the `CLAUDE.md` § Challenging the PM "Don't ask for" list: completing a bounded symmetric set is a routine implementation choice, not a product decision. (PM-which-one calibration is still right when items have *asymmetric* cost or visible-behavior divergence — then the choice is a real fork.)

## Don't queue PM questions behind unrelated blockers

Each PM question lands on its own timeline — do not batch a ready-to-ask question behind an unrelated blocked one ("I'll ask about X once Y resolves"). Blocking a clear question on an unrelated blocker silently delays a decision the PM could make now, and the two timelines have no real dependency. Surface each question when it's ready; don't conflate "these came up in the same session" with "these must be answered together."

## Ship-and-watch telemetry needs a calendared review or a hard tripwire — no third option

When you ship instrumentation/telemetry to "watch and see," there are exactly two legitimate dispositions: (a) a **calendared review** (a dated marker file or recheck that forces someone to look at the data), or (b) a **hard tripwire** (a gate that fires automatically on the measured condition). The third option — ship-and-passively-watch with no forcing function — is the failure mode: nobody looks, the telemetry rots, and the measurement question goes unanswered. Additionally, the **measurement filter must match the doctrine's enumerated target set** — a telemetry probe that measures a broader or different population than the doctrine targets produces data that can't answer the question (the tier-usage telemetry removed 2026-05-18 is the canonical miss: it conflated investigation scouts with the whole `Agent` surface).

## doc-link-checker adds no signal on private-repo absolute self-URLs

The `doc-link-checker` worker (→ `CLAUDE.md` § Reviewer-Routed Workers) cannot verify absolute URLs into private repositories — a GitHub URL pointing at a private repo returns 404 to the checker regardless of validity, producing false-negative noise. **Gate doc-link-checker dispatch on relative-link and public-URL presence**: if a diff's links are all private-repo absolute self-URLs, the checker adds no signal and should be skipped. Route it when there are relative links (resolvable on disk) or public URLs (resolvable over the network) to verify.

## Confirm peer-EM deployment-topology premise with PM at /shape before the pipeline

When a peer-EM recommendation (inbound memo, cross-repo brief) bakes in a **deployment-topology premise** — "both repos ship together," "the consumer runs on the same host," "this is one install surface" — confirm that premise with the PM at `/shape` *before* spinning up the full plan → review → cross-repo-contract pipeline. The topology premise determines whether the work is one coordinated change or two independent ones; getting it wrong means the entire pipeline runs against the wrong shape. This is a `/shape`-altitude convergence question (does the EM understand the deployment topology the same way the PM and peer-EM do?), not something to assume from the memo's framing. → `CLAUDE.md` § Challenging the PM; pairs with `cross-repo-communication.md` § "Memo framing is hypothesis at the architectural altitude too."

## Line-number-keyed allow-lists drift under concurrent multi-session edits

Any allow-list / suppression-list / sidecar that keys entries by **line number** (`filepath:42`, "suppress the finding at line 118") drifts the moment a concurrent session edits the file above that line — the line moves, the key now points at the wrong line, and the suppression either misfires or silently stops applying. Under the shared-workstream-branch model (multiple EM sessions editing the same tree), line-number keys are structurally fragile. **Key on a stable marker instead**: an anchor heading, a unique token in the line, a `# noqa: <rule>` inline comment, or a content hash — anything that survives line-number shift. This is the same failure class as the cross-repo "Four coupled path declarations" lockstep problem, applied to suppression keys.

## ~/.claude/ is a git repo — orphan audits must check git remote + ls-files first

`~/.claude/` (Claude Central / Claude Prime) is itself a git repository with a remote. Any audit that classifies files under `~/.claude/` as "orphans" / "untracked debris" / "candidates for deletion" MUST first run `git -C ~/.claude remote -v` and `git -C ~/.claude ls-files <path>` to check whether the file is tracked and pushed. A file that looks like a stray local artifact may be a committed, remote-backed part of the meta-repo. Classifying tracked-and-pushed content as an orphan and deleting it is data loss masquerading as cleanup. The git remote + ls-files check is the cheap floor before any orphan-deletion call on `~/.claude/` contents.

## Shared-substrate doctrine — distinguish schema-authorship from value-writing

For any registry, schema, or on-disk format that multiple agents/repos read and write, **distinguish who authors the schema (the format owner) from who writes values into it (the contributors)**, or expect sidecar defections. When the two roles are conflated — "whoever needs a field just adds it" — contributors who can't get their field into the shared schema cleanly defect to their own sidecar files, and the shared substrate fragments into N parallel formats. This is the library-vs-service substrate question: a *library* substrate lets any consumer author values against a stable schema owned by one party; a *service* substrate mediates all writes through an owner. Decide which shape the substrate is and name the schema-owner explicitly. Applies to `machine-local/registry.local.toml`, frontmatter schemas, completion-log formats, and any other multi-writer on-disk contract.

## tasks-state-folder-split — load-bearing surface name written under `tasks/`

**Tripwire:** Any write to a load-bearing surface path under `tasks/` instead of `state/`. The full allowlist is the literal STEMS+GLOBS array in `bin/migrate-tasks-to-state.sh`. Common forms — match all of these call shapes:

- **Literal path:** `tasks/lessons.md`, `tasks/handoffs/`, `tasks/orientation_cache.md`, etc.
- **Variable assignment:** `LESSONS_PATH="tasks/lessons.md"`, `HANDOFFS_DIR=tasks/handoffs`
- **Array element:** `paths=("tasks/lessons.md" "tasks/handoffs/")`
- **Kwarg-split:** `--lessons tasks/lessons.md`, `--out tasks/handoffs/`
- **Here-doc:** any `<<EOF` block embedding `tasks/<load-bearing>` text — e.g. `cat >> tasks/lessons.md <<'EOF'` (correct: `cat >> state/lessons.md <<'EOF'`)
- **Constructed path:** language-native path-builders that emit the same string — e.g. JS `path.join(root, 'tasks', 'lessons.md')` or Python `os.path.join(root, 'tasks', 'lessons.md')` / `Path(root) / 'tasks' / 'lessons.md'` (correct: substitute `'state'` for `'tasks'`)

**Offer (the redirect, not the nag):** "did you mean `state/<surface>`? Load-bearing substrate lives under `state/`; `tasks/` is for UUID flight-recorders and ephemera only — see `docs/plans/2026-06-08-tasks-state-folder-split.md`."

**Rationale:** The 2026-06-08 tasks → state split established the bright line so `/distill` and `/update-docs` can sweep `tasks/` aggressively. A load-bearing write under `tasks/` puts the surface in the path of the aggressive sweep — silent data loss is the failure mode this tripwire prevents.

- **Runtime-tripwire (RUNTIME-TRIPWIRE):** Model-aware wall-clock nudge that actuates the `CLAUDE.md` § Subagent Dispatch HARD RULE 15-min executor-runtime ceiling. When an executor crosses its per-model threshold, both channels receive a nudge simultaneously.

  - **Agent-side hook (primary signal):** `hooks/scripts/runtime-tripwire-advisory.sh` — PostToolUse empty-matcher; fires in subagent sessions (hook config inherited); emits `additionalContext` with the wrap-shape prescription. Bark-once per dispatch via `/tmp/runtime-tripwire-agent-${SESSION_ID}` sentinel.
  - **EM-side hook (awareness signal):** `hooks/scripts/runtime-tripwire-em-check.sh` — PostToolUse empty-matcher; fires in EM session; cross-references dispatched-agents ledger; emits one-line nudge naming each overrunning `agentId` + elapsed minutes + model. Single re-nudge at +`RUNTIME_TRIPWIRE_RESTAGE_SECONDS` (default 300 s) via `/tmp/runtime-tripwire-em-restage-${agentId}` sentinel, then silence.
  - **Shared threshold lib:** `hooks/scripts/lib/runtime-thresholds.sh` — sourced by both hooks; exposes `runtime_threshold_minutes(MODEL_ID)`.
  - **Dispatched-agents schema:** `<em_sid>/dispatched-agents.txt` — 4-column TSV: `agentId | model | subagent_type | dispatched-at` (Unix epoch). `dispatched-at` column added by Slice A; legacy 3-column records parse with `dispatched-at = 0`.
  - **Env-var overrides:** `RUNTIME_TRIPWIRE_OPUS_MIN` (default 25), `RUNTIME_TRIPWIRE_SONNET_MIN` (default 12), `RUNTIME_TRIPWIRE_HAIKU_MIN` (default 10), `RUNTIME_TRIPWIRE_RESTAGE_SECONDS` (default 300).
  - **Fire-log surface:** `state/runtime-tripwire-fire-log.tsv` — one record per fire: `timestamp \t agentId \t model \t elapsed_min \t fire_type` where `fire_type` ∈ {`agent-side`, `em-side`}. Intended for triage at `/workweek-complete` Step 4 — wiring TBD.
  - **Greppable token:** `RUNTIME-TRIPWIRE`. **Full doctrine:** `docs/wiki/runtime-tripwire.md`.

## anti-literal tripwires fire on docstring examples — apply noqa marker during tripwire chunk

Anti-literal tripwires (grep-based checks that block usage of banned literal strings) fire on docstring teaching examples that include the literal for pedagogical purposes. Plan the `# noqa: <tripwire-id>` exemption convention upfront during the tripwire chunk — not at validation time. Apply: whenever authoring a new anti-literal tripwire, grep the codebase for docstrings containing the banned literal, and mark them with the exemption comment in the same commit that adds the tripwire. Secondary: parallel executor with safe-commit can absorb concurrent-session pre-staged files — prefer explicit-path commits after executor returns.
