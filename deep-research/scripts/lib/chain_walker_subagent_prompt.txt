## Step 1 — Check the visited-set (cycle / diamond-DAG guard)

Read the visited-set file at:
  ~/.claude/deep-research-claude/chain-walk-$SESSION_ID.json

The file has schema:
  {"session_id": "<uuid>", "started_at": "<ISO8601>", "visited": ["<id>", ...]}

If "$UPSTREAM_ID" is already present in the "visited" array, print:
  "already walked $UPSTREAM_ID (visited-set hit) — returning immediately"
Then return a one-line completion summary and stop. Do NOT re-install.

## Step 2 — Atomically append to visited-set

Before doing any cloning or installation, atomically append "$UPSTREAM_ID" to the
"visited" array in ~/.claude/deep-research-claude/chain-walk-$SESSION_ID.json using stdlib-only Python:

  python3 -c "
# Cross-ported from coord Phase B slice-A F3+F11 (2026-06-15):
# Use a temp-file + os.replace pattern (mirrors _dr_visited_set_append in dep_check.sh)
# for atomic concurrent-safe write. Adds encoding='utf-8' (Windows ANSI codepage hazard).
import json, os, sys, tempfile
path = os.path.expanduser('~/.claude/deep-research-claude/chain-walk-$SESSION_ID.json')
with open(path, 'r', encoding='utf-8') as f:
    data = json.load(f)
if '$UPSTREAM_ID' not in data['visited']:
    data['visited'].append('$UPSTREAM_ID')
dir_ = os.path.dirname(path)
with tempfile.NamedTemporaryFile('w', dir=dir_, delete=False, suffix='.tmp',
                                 encoding='utf-8') as tmp:
    json.dump(data, tmp)
    tmp_path = tmp.name
os.replace(tmp_path, path)
"

If the file does not exist or cannot be parsed, stop and report:
  "ERROR: visited-set file missing or corrupt at ~/.claude/deep-research-claude/chain-walk-$SESSION_ID.json
   This indicates the top-level /deep-research:setup session did not initialise the
   visited-set correctly. Cannot proceed safely."

## Step 3 — Read the upstream's install manifest

Read the file at:
  $SIBLING_PATH/docs/install/agent-install-manifest.json

This is stdlib JSON (no yaml dependency). Parse it to discover:
  - standalone_setup_script.posix  (e.g., "scripts/setup.sh")
  - standalone_setup_script.windows (e.g., "scripts/setup.ps1")
  - direct_deps array (for recursive walking — see Step 5)

If the manifest is missing or unparseable, stop and report the error verbatim.
Do NOT guess at an install path.

The "setup_skill" field in the manifest (e.g., "/deep-research:setup") is
informational metadata — it tells a human what to type to invoke the skill
manually. It is NOT the dispatch primitive. Dispatched subagents do not expand
slash commands in their prompts (coordinator improvement queue 2026-05-08,
line 15). Use standalone_setup_script as the actual invocation target.

## Step 4 — Invoke the upstream's standalone setup script

Detect the platform and run the appropriate script from the upstream's repo root:

On Linux / macOS / WSL:
  bash "$SIBLING_PATH/<standalone_setup_script.posix>" $CONSUMER_INSTALL_ARGS --i-am-agent

On Windows (PowerShell):
  pwsh "$SIBLING_PATH/<standalone_setup_script.windows>" $CONSUMER_INSTALL_ARGS --i-am-agent

The --i-am-agent flag tells the upstream script to emit machine-parseable output
and skip its own interactive y/N prompt. Consumer-side override flags ($CONSUMER_INSTALL_ARGS)
are composed before --i-am-agent per the v2 walker composition contract:
  $CONSUMER_INSTALL_ARGS --i-am-agent [upstream-override-flags...]
When $CONSUMER_INSTALL_ARGS is empty (as for coordinator-claude in v1/v2 schema), the
invocation reduces to the plain --i-am-agent form. If the script does not recognise
--i-am-agent, run without it and treat non-zero exit as failure.

On non-zero exit: stop and report the exit code plus the last 20 lines of output.
Do NOT attempt manual remediation inside this subagent — the upstream's own script
is the canonical install surface.

## Step 5 — Recurse into the upstream's direct dependencies

For each dep in the upstream's direct_deps array where the dep's sibling folder
does not yet exist OR the dep's functional probe fails:

  a. Check the visited-set (Step 1 pattern) — if already visited, skip.
  b. Pre-flight gh auth before cloning:
       gh auth status --hostname github.com 2>&1 | grep -q 'Logged in'
     On auth failure, surface the following and STOP:
       "gh auth check failed. The GitHub CLI is not authenticated.
        Refer to docs/install/AGENT.md in the upstream repo's root
        ($SIBLING_PATH/docs/install/AGENT.md) for auth setup guidance.
        Cannot clone without authentication."
  c. Clone the dep's repo:
       gh repo clone <dep.upstream_url> <../dep.sibling_dir_name>
     If gh is not installed, fall back to:
       git clone <dep.upstream_url> <../dep.sibling_dir_name>
     If both fail, surface the error verbatim and STOP.
  d. Dispatch a fresh subagent (subagent_type: general-purpose, mode: acceptEdits)
     with the contents of the chain_walker_subagent_prompt.txt template, substituting:
       $UPSTREAM_ID  → dep.id
       $SIBLING_PATH → the resolved path to the cloned dep's folder
       $SESSION_ID   → $SESSION_ID  (propagate unchanged — same shared visited-set)
     Wait for the subagent to complete before continuing to the next dep.

Process hard deps before soft deps. Skip optional deps (severity: "optional") unless
the user has explicitly accepted them in a prior session interaction.

## Step 6 — Return a completion summary

After the upstream's script exits 0 and all recursive deps are handled, return:

  "chain-walker done: $UPSTREAM_ID installed successfully.
   visited-set session: $SESSION_ID
   recursive deps walked: <list of dep ids walked, or 'none'>"

If any step failed, return:

  "chain-walker FAILED: $UPSTREAM_ID
   failed at step <N>: <one-line reason>
   session: $SESSION_ID"
