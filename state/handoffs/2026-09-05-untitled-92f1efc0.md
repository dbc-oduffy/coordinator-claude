## What Was Accomplished

Installed coordinator-claude + claude-klabauter from scratch on a Linux cloud container
(Debian, kernel 6.18 x86_64, Python 3.11.15, bash 5.2, **root**, no Homebrew/GPU/GUI/keychain),
walked as an amnesiac agent would walk it, patching far enough to keep going rather than
stopping at the first gate.

**Two PRs open, both from branch `claude/klabauter-linux-compat-6tl37i`:**

- `dbc-oduffy/claude-klabauter#7` — three hard breaks + two correctness fixes + friction log
- `dbc-oduffy/coordinator-claude#43` — two remediation-string fixes + friction log

**Hard breaks fixed (klabauter):**

1. **First-run toolchain was Homebrew-only with no platform or root guard.** Homebrew's
   installer aborts by design as EUID 0, so `_install_homebrew()` returned `EXIT_FAIL` and
   killed the whole first-run flow, reported only as a bare non-zero exit. Added
   `_host_platform()`/`_running_as_root()`, a package-manager ladder (apt-get/dnf/yum/zypper/
   pacman/apk), a formula→distro-package map, a `_pkg_install()` dispatcher, and Linuxbrew
   to the PATH candidates. macOS path untouched and now Darwin-gated.
2. **The warm-engine door does not compile on Linux.** `build_posix.py` pins `-std=c11`,
   which on glibc is strict ISO C and hides POSIX behind feature-test macros — `readlink`,
   `sigemptyset`, `sigaddset`, `CLOCK_MONOTONIC`, `O_CLOEXEC` all undeclared, and under C99+
   that is an error, not a warning. 7 errors, no build. Fixed with `-D_POSIX_C_SOURCE=200809L`
   applied **only off Darwin**. `test_door_install_posix_build.py` 5P/2F → 7/7.
3. **`claude-klabauter.warm.residency` could never reach a verdict on Linux.**
   `ProcessPoolExecutor` forks on Linux, spawns on macOS/Windows, so the warm server's 30
   forked workers inherited its `cmdline` and each matched the resident-server signature. One
   server enumerated as 31, past `_WARM_REACHABILITY_PROBE_CAP` (16), leaving a **hard-severity**
   probe permanently `inconclusive`. Enumeration now drops matches parented by another match.
   Verified live: `inconclusive` → `PASS, all reachable`.

**Also:** `shell_rc_guard` zsh-when-`$SHELL`-unset default made per-platform; `gen_doe_root_pointer`
now finds `machine-local` at `<settings-home>/bin` instead of PATH-only (it reported "not found"
on a box where it worked); `setup.py --skip-fleet-env`; `.gitignore` for `.coordinator-local/`
and `*.egg-info/`; two remediation strings in coordinator-claude that named only brew/winget.

## What I Learned

**`/handoff` cannot run in claude-klabauter at all.** `baton-assemble apply` commits the
artifact into `state/handoffs/`, but klabauter's own `.gitignore` ignores `state/` wholesale
(line 22, pre-existing — present at `HEAD~3`, not introduced by this branch). The result is an
unhandled `RuntimeError` out of `contract/apply_base.py:1357`, not a diagnosed refusal:

```
RuntimeError: git add state/handoffs/<file>.md failed (rc=1): The following paths are
ignored by one of your .gitignore files: state
```

Two parts of the same repo contradict each other. This handoff was written from
coordinator-claude instead, which ignores only three specific `state/` files. Worth deciding
which side gives — and note the failed attempt leaves empty `state/handoffs/` dirs behind that
need manual `rmdir`.

**`repos.doe_claude` is load-bearing for ceremonies, not just for the shell shim.** My friction
log had this as "impact narrower than the message claims — the plugin loads fine, what breaks is
the `claude()` shim and the doctrine-maintainer CLIs". That was right but understated: with it
unset, `baton-assemble brief` dies in `resolution/facade.py` with `OperatorConfigError:
'doe_root' resolved to a corrupt value ''`. So an unset key blocks `/handoff` outright. Anyone
picking this up on a fresh box must `machine-local set repos.doe_claude <coordinator-claude-clone>`
before any baton ceremony will run.

**A Python-level portability audit cannot see the two worst bugs.** Three sweeps (128 hook
files, 1289 across `bin/`+`skills/`, ~4300 in `coordinator_core/`) came back essentially clean —
no hardcoded macOS paths, no BSD-vs-GNU flag hazards, no macOS-only binaries — and that clean
result was *correct*. Both hard breaks were invisible to it: one is a C compiler dialect flag,
the other is a stdlib default (`fork` vs `spawn`) that differs by platform. Do not read a clean
grep sweep as a portability verdict.

**Tests that assert macOS behaviour without pinning the platform pass by accident.** Hit this
twice — `test_build_plan_all_missing_lists_every_install_step` and
`test_resolve_rc_path_default_unset` both encoded the macOS answer with no `sys.platform` pin,
so they described the wrong thing on any Linux runner. Both now pinned with Linux counterparts.
Worth a sweep for the same pattern elsewhere.

**Run the repo's own gate before opening a PR, not after.** `check-persona-names` caught me
quoting the fleet codename `project_rag` verbatim from a registry warning into my own friction
log — a violation my ad-hoc pytest sweeps would never have found. It also flagged
`coordinator_core.egg-info/PKG-INFO`, an artifact the documented install itself creates.

**Two flag traps on `setup.py --with-test-deps`:** combining it with `--register-only` silently
skips the install (register-only short-circuits first), and without `--skip-fleet-env` it drags
the multi-GB fleet-env step along behind it. Also: `run-tests.py` needs `pytest-xdist`, which
the installer classifies as *advisory* and does not provision — so a by-the-book install leaves
the PR template's required command failing with an argparse error (`unrecognized arguments: -n`),
which reads as a broken script rather than a missing dependency.

**`--check` is not an install verification** and returns green on a box whose engine install
crashed. `--preflight` is the flag that actually probes. coordinator-claude's INSTALL.md says
so bluntly; klabauter's advertises `--check` as "deterministic check-only". The `--help` text
now states the limitation inline.

**This container is ephemeral, and this handoff is not durable by default.** It lives at
`state/handoffs/` in a clone that disappears when the container is reclaimed. It is committed
to the branch, so it survives via the remote — but only because coordinator-claude tracks
`state/`. Anything written to klabauter's `state/` in a cloud session is lost outright.
